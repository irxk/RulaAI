# Rula — 自分のPCで動く日本語AIアシスタント

Rula は、NVIDIA の GPU を積んだ Windows PC の中だけで動く、日本語の AI アシスタントです。
チャットの画面で対話でき、会話の内容が外部の AI サービスに送られることはありません。
必要なときは自分で Web 検索・計算・日付の計算をしてから答えます。画像も読めます。

> [!WARNING]
> **無検閲 (uncensored) モデルを使っています。** 会話モデルは、安全のための調整を緩めた
> HauhauCS/Qwen3.5-9B-Uncensored です。拒否のルールはプロンプトで与えているだけで、
> モデルの重みには含まれていません。プロンプトを書き換えれば外せます。詳しくは [NOTICE](NOTICE)。

## かんたん導入 (Windows + NVIDIA GPU)

| 必要なもの | |
|---|---|
| OS | Windows 10 / 11 (64bit) |
| GPU | NVIDIA、VRAM 8GB 以上 (6〜8GB なら軽い 4B モデルを自動で選びます) |
| ドライバー | 551.61 以降 |
| ディスク | 空き約 14GB (導入後は約 8GB) |
| 回線 | 初回に約 7GB をダウンロードします |

Python などを先に入れておく必要はありません(Rula 専用のものをフォルダの中に用意します)。

1. このページ上の **Code → Download ZIP** でダウンロードし、好きな場所に展開します。
2. 展開したフォルダの **`Rula-Setup.cmd`** をダブルクリックします。
   「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」を押します。
3. 表示を確認して Enter を押すと、ダウンロードと準備が進みます(回線により 10〜40 分)。
4. 終わると Rula が開きます。次からはデスクトップかスタートメニューの「Rula」で起動します。

途中で止まっても、もう一度 `Rula-Setup.cmd` を実行すれば、取得済みのファイルはそのまま続きから再開します。
取得するファイルはすべて配布元 (python.org、PyPI、llama.cpp の GitHub、HuggingFace) のもので、
決められた SHA256 と一致しなければ使いません。

### 使い方

- 下の入力欄に書いて Enter で送信します(改行は Shift+Enter)。
- 画像はドラッグ&ドロップか貼り付けで添付できます。
- 生成中は「停止」で止められます。左の一覧から前の会話に戻れます。
- 英語で聞けば英語で答えます。

### アンインストール

このフォルダと `%APPDATA%\Rula`(会話の履歴)、デスクトップとスタートメニューの「Rula」を削除してください。
PC の設定やレジストリには何も書いていません。

### うまく動かないとき

| 症状 | 対処 |
|---|---|
| 「NVIDIA の GPU とドライバーが見つかりません」 | NVIDIA の GPU が必要です。ドライバーを入れてください |
| 「ドライバーが古い」 | NVIDIA App か nvidia.com からドライバーを更新してください |
| 返事がとても遅い | 他の GPU を使うアプリ(ゲーム、動画編集など)を閉じてください。VRAM が足りないと極端に遅くなります |
| ダウンロードが止まる | もう一度 `Rula-Setup.cmd` を実行すると続きから再開します |
| ウイルス対策ソフトに止められる | `Rula-Setup.cmd` はダウンロードと準備だけを行うスクリプトです。中身はテキストで確認できます |

以下は、仕組みと、HTTP API・Discord Bot として使うための詳しい説明です。

## HTTP API として使う

自分のPCで動く日本語アシスタントを、固定URLのHTTP APIとして公開します。
会話の内容が外部のAIサービスに送られることはありません。

```bash
curl -X POST https://api.example.com/v1/chat \
  -H "Authorization: Bearer rula_xxxxx" \
  -H "Content-Type: application/json" \
  -d '{"message": "日本で2番目に高い山は?"}'
```

```json
{
  "answer": "日本で2番目に高い山は北岳で、標高は3,193メートルです。",
  "conversation_id": "Vg3nwDCoC2Ly04KB",
  "searched": ["日本で2番目に高い山"],
  "elapsed_ms": 5043
}
```

## セットアップ

### 1. 依存関係とモデル

```powershell
pip install -r requirements.txt   # 約50MB
.\setup_llama.ps1                 # 9B: 約7.0GB・初回のみ(4B なら -Model 4b で約3.4GB)
```

推論は llama.cpp の `llama-server` が行います。API が起動時に自動で立ち上げ、
API が止まると(強制終了でも)一緒に終了します。PyTorch は不要です。

`setup_llama.ps1` が取得するもの(すべて配布元の SHA256 と照合します):

| ファイル | 9B | 4B | 用途 |
|---|---|---|---|
| llama.cpp b11172 (CUDA 12.4 版) | 616MB | 616MB | 推論エンジン |
| 会話モデル Qwen3.5 無検閲版 Q4_K_M | 5.4GB | 2.6GB | 本体 |
| mmproj | 879MB | 644MB | 画像を会話モデル自身で読む(`-NoVision` で省略) |
| MTP 層 | 160MB | 77MB | 生成を速くする(`-NoMtp` で省略) |
| **ディスク使用量の合計** | **約13GB** | **約7.4GB** | MTP 付きモデルは本体の複製に層を足したもの |

RTX 4060 (8GB) での実測(MTP あり):

| | 9B(既定) | 4B |
|---|---|---|
| VRAM | 約6.0GB | 約3.6GB |
| 生成速度 | 約61〜63 tok/s (MTP 無し 42) | 約87〜105 tok/s (MTP 無し 65〜70) |
| 検索ありの質問 1問あたり | 約6.9秒 | 約5.8秒 |
| 検索なしの知識・推論 10問 | 7問正解 | 4問正解 |
| 画像1枚の読み取り | 約9秒 | 約6秒 |

9B は 8GB のカードでは余裕が 600MB ほどしかありません。ほかのアプリが GPU を
多く使うと、モデルの一部がメインメモリにはみ出して生成が極端に遅くなります
(エラーにはなりません)。その場合は GPU を使うアプリを閉じるか、`.env` で
`RULA_MTP_DRAFT=1`(VRAM -210MB)/ `RULA_MTP=0`(-490MB)にするか、4B に切り替えてください。

Ollama でも動きます(`RULA_BACKEND=ollama`)。その場合、画像は別の画像モデル
(Qwen2-VL-2B)で読むため `pip install -r requirements-torch.txt`(約4.8GB)が必要で、
画像のたびに会話モデルを VRAM から降ろします。設定項目は `.env.example` を参照してください。

### 2. APIキーを発行

```powershell
python make_api_key.py
```

キーは**この時に一度だけ表示**されます。控えてください。

### 3. 固定URLを設定(初回のみ)

Cloudflareに登録済みの独自ドメインが必要です。

```powershell
.\setup_tunnel.ps1
```

ブラウザが開くので、対象ドメインを選んで承認します。以下が自動で行われます。

1. Cloudflareアカウントへの紐づけ
2. トンネル `rula-api` の作成
3. `api.example.com` をトンネルへ向けるDNS設定
4. `tunnel.yml` の生成

### 4. 起動

```powershell
.\run_api.ps1
```

`https://api.example.com` で使えるようになります。**URLは以後変わりません。**

> `setup_tunnel.ps1` を実行していない場合は、`trycloudflare.com` の使い捨てURL
> (起動ごとに変わる)で公開します。

### 5. 常時稼働にする(任意)

```powershell
.\install_autostart.ps1        # ログオン時に自動起動
.\install_autostart.ps1 -Remove  # 解除
```

## デスクトップアプリ(いちばん手軽)

```powershell
.\build.ps1             # Rula.lnk と Rula.exe を作る(1秒未満)
.\build.ps1 -Shortcut   # デスクトップとスタートメニューにも「Rula」を置く
```

**`Rula.lnk` をダブルクリック**すると、Ollama のような画面の専用ウィンドウが開きます。
API の起動もコマンドも要りません。ウィンドウを閉じると Rula も止まり、VRAM が空きます。

| 画面 | できること |
|---|---|
| 左 | チャット一覧(今日 / 過去7日間 / それ以前)。「削除」は2回押すと消えます |
| 中央 | 回答は生成しながら表示。検索中は「検索しています: …」と出ます |
| 下 | 入力欄 (Enterで送信、Shift+Enterで改行、日本語変換中のEnterは送信しません) |
| 📎 | 画像を添付。ドラッグ＆ドロップや貼り付け (Ctrl+V) でも渡せます |
| 考える | ON にすると考えてから答えます (正確になるが遅い) |
| ■ | 生成を途中で止めます |

- 起動から約10秒でモデルの準備ができます(左下の点が緑になります)
- 回答中のリンクは普段のブラウザで開きます
- チャットは `%APPDATA%\Rula\chats` に保存されます(この PC の中だけ)
- ウィンドウは Edge の「アプリモード」です。Rula 専用のプロファイルで、拡張機能と同期を
  無効にして開くので、普段の Edge の履歴・拡張機能・アカウントとは混ざりません
- ログ `%APPDATA%\Rula\rula.log` には状態とエラーだけを書きます(メッセージ本文は書きません)

> **`Rula.exe` について。** 中身は `Rula.lnk` と同じ起動処理を C# で書いた小さなランチャーです。
> ただし署名の無い作りたての exe なので、ウイルス対策ソフトが誤検知して隔離することが
> あります(この PC では Malwarebytes / Tencent PC Manager が実行した瞬間に消しました)。
> exe を使いたい場合は、ウイルス対策ソフトの除外にこのフォルダを追加してください。
> `Rula.lnk` は署名付きの Python 本体を起動するだけなので、誤検知されません。

## 手元のターミナルで話す(CLI)

API を立てずに、その場で対話できます。

```powershell
python -m src.rula --candid          # 対話開始(API と同じ率直モード)
python -m src.rula --candid --stream # 検索結果を使う長い回答を、生成しながら表示
```

| 入力 | 動作 |
|---|---|
| 普通に文章を書く | 答えます(必要なら自動で検索・計算・日付計算) |
| `C:\写真\レシート.png 合計はいくら?` | 文中の画像パスを読み取って答えます |
| `/think` | 思考モードの ON/OFF |
| `/trace` | 検索結果・思考など内部の動きを表示 |
| `/search 語` `/read URL` | 明示的に検索・ページ読み取りしてから答える |
| `/remember 事実` `/memory` `/forget 番号` | ユーザーについての記憶(`data/rula_memory.json`) |
| `/reset` | 会話をリセット(記憶は残る) |
| `/help` `/exit` | コマンド一覧 / 終了 |

API が起動中なら、CLI は API が立てた llama-server をそのまま使います(VRAM は
増えません)。生成は1件ずつなので、同時に使うと互いに待ち合わせになります。

## なぜポート開放が要らないのか

APIは **127.0.0.1 のみ**で待ち受けます。外部からの到達は `cloudflared` が担当し、
**こちらからCloudflareへ**接続しに行く仕組みです。ルーターに着信を通す必要がなく、
サーバーがインターネットに直接晒されることもありません。

## OpenAI互換で使う(推奨)

**OpenAIのクライアントライブラリやツールがそのまま使えます。**
`base_url` を差し替えるだけです。

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://api.example.com/v1",
    api_key="rula_xxxxx",
)

r = client.chat.completions.create(
    model="rula-1.2-4b",
    messages=[{"role": "user", "content": "日本で2番目に高い山は?"}],
)
print(r.choices[0].message.content)
```

ストリーミング(`stream=True`)にも対応しています。LangChain、LibreChat、
SillyTavern など、OpenAI互換のエンドポイントを指定できるツールで動きます。

> **`model` に何を書いても同じモデルが答えます。** `rula-1.2-4b` は互換のための
> 固定名で、実際に動いているモデルは `/health` の `weights`(既定は `Rula2.0-9b`)で
> 確認できます。名前の末尾を `-think` にすると思考モードになります。

> **`base_url` は `/v1` の有無どちらでも動きます。** ツールによって
> `https://api.example.com/v1` を要求するものと `https://api.example.com` を
> 要求するものがあり、404の最大の原因になるため、両方で受けるようにしています。

`messages` の `content` は**文字列と配列の両方**を受け付けます。

```json
{"role": "user", "content": "ああ"}
{"role": "user", "content": [{"type": "text", "text": "ああ"}]}
```

## 回答の長さ

**既定は簡潔(2〜4文)です。** APIは短い応答を求められることが多く、長い回答は
クライアントのタイムアウト(`context canceled`)の原因にもなるためです。

長くしたい時は**明示的に頼みます**。「詳しく」「長文で」「まとめて」「解説して」
「考察」「分析して」「レポート」などが引き金です。

| 質問 | 時間 | 長さ |
|---|---|---|
| こんにちは | 1.3秒 | 21字 |
| 日本で2番目に高い山は? | 6.4秒 | 95字 |
| AIについて教えて | 7.8秒 | 247字 |
| AIについて**詳しく解説して** | 100秒 | 2,067字 |

以前は「AIについて教えて」だけで156秒・3,338字かかっていました。
既定を簡潔に振ったことで**20倍速く**なっています。

長さの既定を変えたい場合は `api.py` の `BRIEF_TOKENS` / `DETAILED_TOKENS` を
調整してください。

## 思考モード(think)

**答える前に考えさせます。** 推論・計算・条件の比較検討で正答率が上がります。
既定は**オフ**です(遅くなるため)。

指定方法は3つあり、どれでも結果は同じです。**クライアントが使えるものを選んでください。**

```python
# 1. モデル名で指定 — モデル名しか選べないツール(SillyTavernなど)向け
r = client.chat.completions.create(
    model="rula-1.2-4b-think",
    messages=[{"role": "user", "content": "連続する3つの整数の和が72。真ん中の数は?"}],
)

# 2. OpenAI標準の reasoning_effort
r = client.chat.completions.create(
    model="rula-1.2-4b",
    reasoning_effort="high",      # none / minimal / off 以外はすべてオン
    messages=[...],
)

# 3. 独自形式の /v1/chat なら think フィールド
#    {"message": "...", "think": true}
```

`/v1/models` には `rula-1.2-4b` と `rula-1.2-4b-think` の2つが並びます。
中身は同じモデルで、思考の有無だけが違います。

**思考の過程は既定では回答本文に混ざりません。** 別のフィールドに入ります。

| エンドポイント | フィールド |
|---|---|
| `/v1/chat/completions` | `choices[0].message.reasoning_content` |
| `/v1/chat` | `thinking` |

対応クライアントでは折りたたみの「思考中」表示になり、非対応のクライアントは
このフィールドを無視して回答だけを表示します。

### 思考を画面に表示する(think-stream)

`reasoning_content` を読まないクライアント(Discord Bot、簡易フロントなど)では、
上のままだと思考が**どこにも出ません**。`think-stream` を指定すると、思考が
**回答本文(`content`)そのものに入る**ので、どんなクライアントでも表示されます。

```jsonc
{"model": "rula-1.2-4b", "think-stream": true,
 "messages": [{"role": "user", "content": "連続する3つの整数の和が72。真ん中の数は?"}]}
```

返ってくる `content`:

```
💭 連続する3つの整数を n-1, n, n+1 とすると、和は 3n。3n = 72 なので n = 24。

---

真ん中の数は **24** です。
```

**指定すると `think` は自動的に有効になります**(思考を見たいなら思考は要る)。

#### 値の書き方

**どの書き方でも通ります。** 迷わなくて済むように、意図的に緩く受けています。

| 値 | 意味 |
|---|---|
| `true` / `"on"` / `"inline"` / `"show"` | 既定の書式(`💭 …` + 区切り線) |
| `false` / `"off"` / 未指定 | 本文には入れない(既定) |
| `"<思考>{}</思考>\n\n"` | `{}` の位置に思考が入る |
| `"【考え中】"` | 置換記号が無ければラベル扱い。下に思考が続きます |

`{}` の代わりに `{thinking}` `{think}` `{reasoning}` も使えます。
フィールド名は `think-stream` と `think_stream` のどちらでも受け付けます。

> **思考は片方にしか入りません。** `think-stream` を指定した場合、
> `reasoning_content` は空になります(両方に入れると、両方を描画する
> クライアントで思考が二重表示になるため)。
> ただし `/v1/chat` の `thinking` フィールドは常に埋まります。

### リアルタイム配信

`stream=true` のとき、思考は**生成されているそばから届きます**。まとめ送りでは
ありません。「考え中…」の表示が実際に文字で動きます。

実測(`stream=true`、思考あり):

| | 値 |
|---|---|
| 最初のチャンク到着 | **0.4〜0.8秒** |
| チャンク数 | 1回の回答で 95〜370個 |
| 配信が続く時間 | 4〜9秒(思考が終わるまで) |

流れる先は `think-stream` の指定で変わります。タイミングは同じです。

| 設定 | 思考が流れるフィールド |
|---|---|
| 指定なし | `delta.reasoning_content` |
| `think-stream` あり | `delta.content` |

**回答本文は最後にまとめて送られます。** 思考と違い、生成途中の回答は
差し替わることがあるためです(ツール呼び出しだと判明する、拒否検出で
再生成される、など)。一度送ったチャンクは取り消せないので、確定してから
送っています。時間のほとんどは思考側なので、体感の差はほぼありません。

> **思考オフのときは従来どおり**まとめ送りです(流すものが無いため)。

> **応答が時々もたつく場合、原因はVRAMの空きです。** 計測時点でGPUは
> 7.5GB/8.2GB使用済みで、他アプリ(ブラウザ、Discord、ゲームランチャー等)と
> 取り合っていました。空いている状態では初回0.06〜0.67秒・生成58トークン/秒で
> 安定しますが、混んでいると最初のチャンクまで数秒〜20秒待つことがあります。
> これはRula側ではなくGPUの空き待ちです。

### 効果と代償(実測)

答えが一つに決まる問題6問を、各2回ずつ聞いた結果:

| | 正答 |
|---|---|
| 思考なし | 5/12 |
| **思考あり** | **11/12** |

思考なしでは「時速60kmで2時間、時速90kmで1時間走った平均時速」に120km/h、
「6人の総当たり戦の試合数」に30試合(正解15)と答えました。回答の途中で
自分の誤りに気づいて訂正を始めることもあります。

代償は時間です。同じ質問を12回ずつ計測した中央値:

| | 中央値 | 範囲 |
|---|---|---|
| 思考なし | 0.7秒 | 0.2〜6.8秒 |
| **思考あり** | **9.6秒** | 5.0〜15.3秒 |

**+約9秒**が目安です。思考の長さは質問によって変わるため、ばらつきがあります。
検索と「詳しく」が重なる最も重いケースでは21秒→42秒でした。
常時オンにしていないのはこのためです。

> 思考は回答と同じトークン予算から出ていきます。そのため思考時は `THINK_TOKENS`
> の分だけ予算を上乗せし、代わりに続き生成(`max_continuations`)を1回に絞って
> います。両方を許すと、最も重いケースが63秒まで伸びました。

### 思考の打ち切り

**このモデルは自力で思考を止められないことがあります。** 答えの出ない問い
(嘘つきパラドックスなど)を与えると、同じ論点を言い換えながら予算を使い切り、
**回答が1文字も残らない**まま終わります。4回試して4回とも再現しました。

対策として、思考が `RULA_THINK_CHAR_CAP`(既定 **12,000字**)に達したら生成を
打ち切ります。打ち切った思考は捨てず、検討メモとして回答の生成に渡します。
同じ内容が3回連続で現れた場合も、そこで止めます。

既定値は実測から決めています。**検索結果を読むターンは正当に長く考えます。**

| ターン | 思考 | 回答 |
|---|---|---|
| 通常の計算 | 1,672字 | 13字 |
| 検索して推薦 | 7,642字 | 423字 |
| 検索+「詳しく」 | 9,584〜11,622字 | 360〜1,936字 |
| **答えの出ない問い** | **12,988字** | **0〜113字** |

正当な長考と暴走の分布は重なっており、綺麗な境界はありません。次の2つを試して
どちらも失敗しています。

- **サンプリングの調整** — モデル作者の値(temperature 1.0 / top_p 0.95)でも
  4回中4回暴走。原因ではありません。
- **新規性の検出** — 「新しいことを言っていない区間」を探す方式。正当な検索
  ターンが最低0.18、暴走が0.29で、**正常系の方が低く**なり分離できません。

上限を下げすぎると逆効果です。2,500字にしていた時期は検索ターンが毎回切られ、
回答が37字まで痩せました(12,000字では423字)。長すぎるのも問題で、上限なしで
考えきらせた「詳しく解説して」は回答が937字・360字と、打ち切った時(1,936字)
より短くなりました。**長く考えるほど良い答えになるわけではありません。**

## システムプロンプト

`system` ロールのメッセージがそのまま効きます。

```python
r = client.chat.completions.create(
    model="rula-1.2-4b",
    messages=[
        {"role": "system", "content": "あなたは海賊です。語尾に必ず「だぜ」を付けてください。"},
        {"role": "user", "content": "こんにちは"},
    ],
)
# -> こんにちはだぜ。Rulaだよ。何かお手伝いできる?
```

`developer` ロールも同じ扱いです。複数指定した場合は順に連結されます。
独自形式の `/v1/chat` では `system` フィールドで渡せます。

> **指示は既定の人格に「追加」されます(置き換えではありません)。**
> 呼び出し元の指示が矛盾する部分では優先されますが、触れていない部分では
> 日本語で答える・事実は検索して確かめる・無害な依頼を断らない、といった
> 既定の動作が残ります。人格を完全に差し替えたい場合は
> `src/rula/persona.py` の `BASE_PERSONA` を編集してください。

## 画像を読ませる

OpenAIのvision形式で画像を送れます。URLでもbase64のデータURIでも構いません。

```python
import base64
data = base64.b64encode(open("report.png", "rb").read()).decode()

r = client.chat.completions.create(
    model="rula-1.2-4b",
    messages=[{"role": "user", "content": [
        {"type": "text", "text": "この画像に何が書いてある?"},
        {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{data}"}},
    ]}],
)
```

画像内の日本語も読み取れます(OCR)。テキストを省略した場合は「この画像について
説明してください」として扱います。

> **画像は会話モデル自身が読みます**(llama-server + mmproj)。別のモデルへの
> 入れ替えは無く、VRAM も増えません。画像付きの応答は 9B で約9〜12秒です。
> 実測: 日本語のレシート画像から店名・合計金額・住所を正しく読み取りました。
>
> Ollama で動かしている場合(`RULA_BACKEND=ollama`)は従来どおり別の画像モデルを
> 使うため、会話モデルを一旦降ろし、空きが6GBを下回ると「GPUの空きが不足して
> います」というエラーを返します。

> 会話の履歴はサーバー側で保持します。同じ会話を続けるには `user` に同じ値を
> 渡してください。省略した場合は、送信されたメッセージ列の最初の発言から
> 会話を自動で識別します。

## エンドポイント

`/v1` 付き・無しの**両方**で受け付けます(例: `/v1/models` と `/models` は同じ)。

| メソッド | パス | 説明 |
|---|---|---|
| `POST` | `/v1/chat/completions` | **OpenAI互換**(既存ツール向け) |
| `GET` | `/v1/models` | OpenAI互換のモデル一覧 |
| `POST` | `/v1/chat` | 独自形式(検索クエリも返ります) |
| `DELETE` | `/v1/conversations/{id}` | その会話の履歴を消す |
| `GET` | `/health` | 稼働確認(認証不要) |
| `GET` | `/` `/v1` | エンドポイント一覧(認証不要) |

`temperature` や `max_tokens` は受け取りますが**無視されます**(サーバー側で固定)。
クライアントが常に送ってくるため、エラーにせず受理する作りです。
`reasoning_effort` は例外で、**思考モードの切り替えとして実際に効きます**。

`POST /v1/chat` のパラメータ:

| 項目 | 必須 | 説明 |
|---|---|---|
| `message` | ○ | 質問(最大4000文字) |
| `conversation_id` | | 同じ値を渡すと会話が継続。省略すると毎回新規 |
| `reset` | | `true` でその会話の履歴を消してから回答 |
| `system` | | 追加のシステム指示(既定の人格に追加される) |
| `think` | | `true` で考えてから答える(既定 `false`) |
| `think-stream` | | 思考を `answer` にも入れる。`true` か書式文字列 |

対話ドキュメントは `http://127.0.0.1:8000/docs` で見られます。

## Discord Bot

`DisBot/discord_bot.py` は、メンションすると答えるBotです。**APIの利用者の一人**として動きます
(モデルは読み込まず、`127.0.0.1` のAPIを叩くだけ)。生成はAPI側で1件ずつ直列に処理されるため、
GPUの取り合いは起きません。

### 準備

1. [Discord Developer Portal](https://discord.com/developers/applications) で
   **New Application** → **Bot** タブ → **Reset Token** でトークンを取得
2. 同じ画面の **Privileged Gateway Intents** で
   **MESSAGE CONTENT INTENT** を **ON**(これが無いと本文を読めません)
3. **OAuth2 → URL Generator** で `scopes: bot`、権限は
   **Send Messages** と **Read Message History** を選び、出たURLでサーバーに招待
4. `.env` に追記

```ini
DISCORD_TOKEN=<Botトークン>
RULA_API_KEY=rula_xxxxx     # make_api_key.py が表示したキーそのもの
```

> `.env` の `RULA_API_KEY_SALT` / `RULA_API_KEY_HASH` は照合用です。ここからキーは
> 復元できないので、控えが無ければ `python make_api_key.py` で再発行してください
> (**古いキーは無効になります**)。

### 起動

APIを起動したまま、別のウィンドウで実行します。

```powershell
.\run_api.ps1            # 1つ目のウィンドウ
.\DisBot\run_bot.ps1     # 2つ目のウィンドウ
```

Botのファイルは `DisBot/` にまとまっています。設定は1つ上の `RulaAI\.env` を
共有します(APIキーがそこにあるため)。`DisBot\.env` を置けばそちらが優先されます。

### 話しかけ方

| きっかけ | 動作 |
|---|---|
| `@Rula 東京の人口は?` | 答えます |
| Rulaの発言に返信 | メンション不要で会話が続きます |
| DM | 「DMには対応していません」と案内を返します(同じ人には5分に1回まで)。答えはしません |
| `@everyone` | **反応しません**(告知のたびに答えてしまうため) |
| 画像を添付 | 読み取って答えます(OCR含む) |
| 他のBotの発言 | 無視します |

会話の記憶は**チャンネル単位**です。同じチャンネルなら「じゃあ4人だと?」のような
続きが通ります。

### 設定(`.env`、いずれも任意)

| 変数 | 既定 | 内容 |
|---|---|---|
| `DISCORD_THINK` | `auto` | `auto` 計算・比較・理由を問う質問だけ考える / `on` 毎回考える / `off` 考えない |
| `DISCORD_GUILDS` | (無制限) | 応答するサーバーをIDで限定 |
| `RULA_API_BASE` | `http://127.0.0.1:8000` | 接続先API。**別ホストで動かすなら必須**(下記) |

`.env` の代わりに環境変数でも設定できます。**環境変数が優先**されます。

### 別のホストでBotを動かす場合

Botだけをレンタルサーバーや VPS に置き、APIは自宅PCで動かす構成にできます。
その場合、Bot側の `127.0.0.1` は**そのホスト自身**を指すため、既定のままでは
`Cannot connect to host 127.0.0.1:8000` で起動できません。トンネルの公開URLを指定します。

```ini
RULA_API_BASE=https://api.example.com
RULA_API_KEY=rula_xxxxx
DISCORD_TOKEN=<Botトークン>
```

ホスティングサービスに `.env` を置けない場合は、環境変数として設定してください。

この構成では以下に注意してください。

- **PCの電源が入っていて、トンネルが動いている必要があります。** APIに繋がらない
  状態でもBotはDiscordに接続し、質問されたときに「⚠️ APIサーバーに接続できません」と
  返します(復帰すれば自動的に答えられるようになります)。
- **APIキーがそのホストに保存されます。** キーを持つ人はあなたのGPUを使えます。
  信用できないホストには置かないでください。
- レート制限20回/60秒はトンネル経由でも同じです。

### 表示形式(埋め込み)

**応答はすべて埋め込み(Embed)で返します。** 状態は左端の色でわかります。

| 状態 | タイトル | 色 |
|---|---|---|
| 順番待ち | ⏳ 順番待ちです… | グレー |
| 思考中 | 💭 考えています… | グレー |
| 回答 | (なし) | ピンク |
| エラー | ⚠️ エラー | 赤 |

思考は生成されるそばから埋め込みに流れ込み、回答が出たらその回答に置き換わります。

```
┌ 💭 考えています…
│ > …90 ÷ 40 = 2.25 時間。0.25 時間は 15 分だから
```

埋め込みにした利点は2つあります。

- **1通あたり4096字**まで入ります(平文は2000字)。実測500字前後の回答なら、
  ほぼ確実に1通で収まります。
- **埋め込み内のメンションは通知を飛ばしません。** モデルの出力に `@everyone` が
  混ざっても無害です(`AllowedMentions.none()` と合わせて二重の保険)。

編集はDiscordのレート制限に合わせて1.5秒に1回までです。実測では1回の回答あたり
**1〜4回**の編集で収まりました。

### 実測(ローカルAPI、`rula-1.2-4b`)

| 質問 | think | 最初の表示 | 全体 | 回答 |
|---|---|---|---|---|
| こんにちは。調子はどう? | off | 0.80秒 | 0.8秒 | こんにちは。正常です。 |
| 時速40kmで90km走ると何時間何分? | on | 0.42秒 | 2.3秒 | **2 時間 15 分** |
| りんご12個を3人で等分すると? | on | 5.25秒 | 10.2秒 | 12個÷3人＝4個です。 |
| (続けて)では4人だと? | on | 0.54秒 | 2.2秒 | 12個÷4人＝3個です。 |

最後の行は、チャンネル単位の記憶が効いていることの確認です(「りんご12個」を渡し直していません)。
時間のばらつきはGPUの空き待ちによるもので、他のアプリがVRAMを使っていると伸びます。

### 制限

- **同時に答えられるのは1件です。** GPUが1枚なのでAPI側でも直列化されており、
  混んでいる間は「⏳ 順番待ちです…」と表示されます。重い質問1件が最大5分
  (APIの生成タイムアウト)Botを塞ぐ可能性があります。
- 4096字を超える回答は自動で分割して連投します。コードブロックは分割時に
  閉じ直すので崩れません。ただし実際の回答は500字前後に収まることが多く、
  分割は保険です。
- レート制限はAPIキー単位で20回/60秒です。Botはキーを1つ共有するため、
  この上限はサーバー全体で共有されます。

## APIキー

使うのは `make_api_key.py` の実行時に表示される `rula_` で始まる文字列です。

```
============================================================
  APIキー(この行の文字列をそのまま使います)
============================================================

  rula_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

**`.env` の中身はAPIキーではありません。**

| 項目 | 正体 |
|---|---|
| `RULA_API_KEY_SALT` | 照合用のソルト |
| `RULA_API_KEY_HASH` | キーのハッシュ。ここから元のキーは復元できません |
| `RULA_HOSTNAME` | 公開するURL |

- **有効期限はありません。** 無効化したい場合は `make_api_key.py` を再実行すると、
  その時点で古いキーが使えなくなります。
- 発行時に**一度だけ**表示されます。控え忘れた場合は再発行してください。
- 照合は定数時間比較で行い、一致した文字数がタイミングから漏れないようにしています。

## できること・できないこと

| 機能 | 状態 |
|---|---|
| 日本語での対話 | ○ |
| Web検索 | ○ 事実を問う質問では自動で検索します |
| ページ読み取り | ○ URLを渡すと本文を読みます |
| 画像読み取り(OCR含む) | ○ URLまたはbase64のデータURIで送れます |
| 会話の記憶 | ○ `conversation_id` 単位。約8往復を超えると、古い分を要約して残します |
| Discord Bot | ○ `DisBot/discord_bot.py`。サーバー内のメンションと返信に答えます |
| 率直モード(候補) | ○ **既定で有効。下記「率直モードについて」参照** |
| 思考モード | ○ **リクエスト単位で指定。既定はオフ(速度優先)**。オフでも数量を問う文章題だけは自動で考えます |
| 画像生成 | × このビルドには含まれません |
| 計算 | ○ 式を含む質問は計算ツールで計算します(モデルの暗算は使いません)。回答に書かれた計算も検算して直します |
| 日付計算 | ○ 「クリスマスまであと何日」「100日後は何曜日」などはコードで数えます |

## 正答率を上げている仕組み

答えが確かめられる 30 問(事実 10・文章題 10・言葉の意味 5・ツール 3・雑談 2)を
9B で2周ずつ解かせ、間違え方を見ながら足したものです。採点は「回答の最初の一文に
正解が入っているか」で、どの版も同じ基準で付け直しています。

| 版 | 正解 | 1問の平均 | 残った誤り |
|---|---|---|---|
| 改良前 | 26/30 (87%) | 4.6秒 | 平均時速、連続整数、方程式、確信犯 |
| 文章題の自動思考・計算の検算・意味の回答形式 | 57/60 (95%) | 10.2秒 | 検索の失敗2件(北岳を石川県、利根川)、総当たり30試合 |
| 検索の再試行・Wikipedia の直接参照 | 58/60 (97%) | 11.5秒 | すべからく、1〜100の和を2550 |
| 答えと式の突き合わせ・検索の時間上限 | 57/60 (95%) | 8.2秒 | すべからく、鶴亀を3匹、曜日を「土です」 |
| 辞書・解き直し・曜日の表記 | 60/60 (100%) | 6.9秒 | — |
| 最終版 | 60/60 (100%) | 7.4秒 | — |

**この 30 問は改良に使った問題なので、100% は割り引いて見てください。** そこで、
改良に一度も使っていない 25 問(事実 8・文章題 8・意味 5・ツール 2・雑談 2)を
別に用意して確かめました。

| | 正解 | 主な誤り |
|---|---|---|
| 未使用の 25 問 × 2周(上の表で 60/60 になった時点) | 40/50 (80%) | 枕草子の作者を紫式部(検索せず)、1〜50の和を1170、意味の答え方 |
| 同じ 25 問 × 2周(最終版) | 49/50 (98%) | 「煮詰まる」の1回(内容は正しく、採点の言い回しが合わなかったもの) |

未使用の問題で見つかった誤りも直したので、2回目の 49/50 も完全に未使用の
問題での成績ではありません。それでも、1回目に誤った問題の多くは個別の答えでは
なく仕組み(検索の振り分け、式の読み取り、挨拶)で直っています。

### 幅広いテスト(99問)

上の 2 つは短い質問だけなので、それまで測っていなかった種類を 99 問で確かめました。
数学 26・論理 8・会話(2往復) 10・英語 10・コード 12・要約 5・長文と指示 9・事実 14・
言葉の意味 5。採点は機械で行い、コードは実際に動かしてテストします(モデルが書いた
コードは、ファイル・通信・外部プロセスを使うものを実行前に拒否し、残りを使い捨ての
フォルダで制限時間つきで動かします)。

| 版 | 正解 | 主な誤り |
|---|---|---|
| 改良前 | 73/99 (74%) | 英語に日本語で回答(9問)、コードをコードブロックに入れない(6問)、仕事算の計算ミス、仮定の日付 |
| 英語・コード・計算の確認・振り分け | 87/99 (88%) | 曜日の推論、数列で答えが最後、箇条書きの数、「私の名前は?」に「まだ聞いていません」 |
| 検索の並列化・曜日・数列・項目数・記憶 | 93/99 (94%) | 字数の指定、ツールの曜日を無視、図形の問題 |
| 最終版(字数・図形・「それ」・ツールの曜日・前の発言の数字) | 97/99 (98%) | 「3の倍数でも5の倍数でもない数」を「3の倍数だが5の倍数でない数」と読み違え(式の確認で食い違いを見つけて解き直したが、同じ読み違えのまま)、「富士山より高い山は?」に「旭岳」 |

同じ最終版で、最初の 30 問は 30/30、未使用の 25 問は 2 周で 49/50(「さわり」1回)でした。

採点はすべて同じ基準で付け直しています。採点の言い回しが狭すぎた 5 問(「0.875」を
7/8 と認めない等)は、記録を残したうえで正解の幅を広げました。

- **文章題は自動で考えてから答えます。** 思考モードがオフでも、数量を問う文章題
  (「鶴と亀が合わせて10匹…亀は何匹?」など)だけは考えます。思考は 2,000 字で
  打ち切ります(上限なしでは同じ種類の問題で 4〜74 秒とばらつきました。文章題
  36 問で 3,000 字と比べ、正答は同じ全問で、平均は 18.1 秒 → 13.2 秒)。
  `.env` の `RULA_AUTO_THINK_CAP` で変えられます。
- **回答に書かれた計算はすべて検算します。** 「2500 × 0.88 = 2168」のような誤りは
  正しい値に置き換え、その値を使った後の式と最初の一文の答えも直します。
  モデルに書き直させるのは、それで直らない場合だけです。
- **最初の一文の答えと、最後の式の結果を突き合わせます。** 「2550 です」と答えて
  「式: 50 × 101 = 5050」で締めた回答は、式の側に合わせます。ただし式が検算用
  (問題文の数字を再現するもの)の場合や、本文の途中にその答えの根拠がある場合は
  触りません。保存済みの 180 回答に当てて、変わったのはこの1件だけでした。
  「式: 8*(8-1)/2」のように結果を書いていない式も、計算した値で突き合わせます。
- **自分の検算が問題文と合わない回答は、解き直します。** 「亀は3匹」と答えて
  「4 × 3 + 2 × 7 = 28」で確かめた回答は、実際は26なので答えの方が誤りです。
  この場合は式を26に直すのではなく、合わなかったことを伝えて考え直させます。
  途中の計算がコードで直せない文章題も同じく解き直します(書き直しを頼むと、
  指摘への反論を回答として書いたことがあったため)。問題文の数字は、検算でも
  決して書き換えません。解き直しても合わなければ元の回答を残します。
- **言葉の意味はウィクショナリー(辞書)を先に引きます。** 「〜の意味は」「〜とは」
  の質問では、辞書の語義を検索結果の先頭に置きます。誤用とされる語義には辞書
  自身が「誤用」と書いているので、取り違えにくくなります。検索エンジンが全滅した
  場合で比べると、辞書なしでは すべからく・役不足・確信犯 を 18 回中 18 回とも
  誤用の意味で答え、辞書ありでは 18 回とも本来の意味で答えました。
- **検索は Wikipedia を直接引きます。** 質問の主題がそのまま記事名と一致する
  場合(「北岳は何県」→「北岳」、「「役不足」の意味」→「役不足」)だけ、その記事の
  冒頭を検索結果の先頭に置きます。編集者が作った転送(「日本の国鳥」→「キジ」)
  はたどります。一致しなければ使いません(別の記事が先頭に来ると誤答のもとに
  なるため)。検索ライブラリ自身の Wikipedia 検索はあいまい一致の1件目を先頭に
  置くので(「日本の国鳥」に「日本の国旗」)、結果の最後に回します。
  Wikimedia から回数制限(429)が返ったら、指定された秒数は問い合わせません。
- **「〜の作者は?」「〜の首都は?」も検索します。** 疑問詞のない属性の質問は
  検索されず、記憶だけで「枕草子の作者は紫式部」と答えていました。
- **検索エンジンが遅いときは別のエンジンも並行して使い、全体で 12 秒を上限にします。**
  最初のエンジン群が失敗したらすぐ、4 秒以内に返らなければその時点で次の群も
  走らせ、先に返った結果を使います。再試行なしでは 12 回中 2 回が失敗し、その
  ターンはモデルの記憶だけで答えて北岳を石川県などに置いていました。順番に待つ
  方式では、エンジンが混んでいた回に 34 回中 26 回が 8 秒待たされていました。
  上限は、エンジンが応答しないときに 1 問 70 秒以上かかったことから入れています。
  ページの読み込みも全体で 10 秒までです。
- **同じ検索は 10 分間キャッシュします。** 待ち時間がなく、検索エンジンの
  回数制限にも当たりにくくなります。
- **細かい書き方の癖も直します。** 質問を繰り返しただけの1行目(「弟は何歳ですか？」)
  は消します。曜日は「土曜日」と書かせます(「(土)」と渡すと「土です。」と答えた
  ため)。文章題で考えた後の回答は、考える用に広げた長さではなく通常の長さで
  書かせます(広げたままだと 2,581 字の回答になったことがあるため)。
  挨拶には挨拶で返させます(「おはよう」に「Rula2.0-9bです」と名乗るだけの返事が
  6 回中 3 回ありました。指示後は 30 回中 30 回が挨拶で始まりました)。
- **中国語の混入を直します。** 基盤モデル(Qwen)の癖で、570 回答中 4 回に中国語が
  混ざりました。「时针」「总价」のような1〜2語は日本語の字(時針・総価)に置き換え、
  段落ごと中国語になったものはその段落だけを日本語に訳させます(「日本語で書き直して」
  と頼むと中国語をそのまま写し返したため、訳すように頼みます)。「我们」「斐波那契」
  のように字の置き換えでは直らない単語は、単語ごと日本語(私たち・フィボナッチ)に
  します。中国語について聞かれた場合は触りません。
- **文章題の答えは、式をコードで計算して確かめます。** 回答とは別に、答えを求める
  計算だけをモデルに式で書かせ(「答え = 1 / (1/12 + 1/6)」)、それを分数のまま正確に
  計算します。回答の答えと一致すればそのまま、食い違えば両方の値を見せて解き直させ、
  解き直した答えが計算と一致した時だけ差し替えます(3つのうち2つが一致した方)。
  式の計算は安全な計算器で行い、プログラムとしては実行しません(四則演算と
  組み合わせ・最大公約数などの決まった関数だけ。import・ファイル・ループは拒否)。
- **英語の質問には英語で答えます。** 以前は英語の 10 問中 9 問に日本語で答えていました。
  文の終わり方で判定するので、「What does いただきます mean?」は英語、
  「OK Google って何?」「I love you を日本語で」は日本語で答えます。「英語で要約して」
  のように英語を頼まれた場合も英語です。
- **コードはコードブロックに入れます。** 以前は 12 問中 6 問でコードを ``` で
  囲まず、画面上でインデント(Python では文法の一部)が崩れていました。囲み忘れた
  場合も、関数定義から始まるまとまりを自動でコードブロックにします。
- **渡した文章への作業(要約・翻訳など)では検索しません。** 「次の文章を要約して」
  の後に続く文章の中身ではなく、指示の部分で質問の種類と言語を判定します(文章中の
  「個人差」の「差」で比較の質問と判定され、要約を Web 検索していたため)。
- **ユーザー本人についての発言は検索に送りません。** 「私は1990年生まれです」という
  発言が、回答の事実確認のためにそのまま検索語になっていました。本人についての
  質問(「私の名前は?」)や、「それより高い山は?」のように前の話を指す質問も検索
  しません(「それ」が何かは会話に書いてあり、そのまま検索すると別の山の情報を
  拾って誤答したため)。
- **仮定の日付も計算します。** 「今日が水曜日だとすると、100日後は何曜日?」を、
  以前は実際の今日(土曜日)で計算していました。「ある月の1日が月曜日のとき、
  15日は何曜日?」もコードで数えます。日付ツールが出した曜日と回答の曜日が違えば、
  ツールの方に合わせます(ツールが「月曜日」と出しても、モデルが自分で数え直して
  6 回中 4 回「水曜日」などと答えたため)。
- **「式:」の行は書き方を揃えてから検算します。** 「式: `calc: 3000*(1-0.15)` ->
  結果: 2955」のように、ツールを使ったふりをした結果(実際は2550)を書くことが
  ありました。矢印やバッククォートを含む式は検算の対象外だったため、式の行だけ
  「式 = 結果」の形に直してから確かめます。
- **「それ」を前の話題で補います。** 「富士山の標高は?」の後の「それより高い山は
  日本にある?」を「「富士山」より高い山は日本にある?」として扱います。
- **前の発言の数字を使う短い問いも文章題として扱います。** 「3人で12000円の食事を
  しました。」の後の「1人あたりいくら?」は、単独では文章題に見えず、モデルが検索して
  正社員の人件費の話で答えていました。
- **考えた後に書かれたツール呼び出しも実行します。** 考えた後の本文が「calc: 100 -
  (100//3 + …)」の1行だけになり、それがそのまま答えとして表示されたことがありました。
- **累乗(2^3、2**3)を含む計算も検算します。** 「7 / (2^3) = 0.421875」(実際は
  0.875)が見逃されていました。
- **字数の指定を守ります。** 「50字以内」「200字程度」から外れたら、字数を伝えて
  書き直させます。「以内」を書き直しても超える場合は、文の切れ目で切り詰めます。
- **頼まれた数・口調を守ります。** 「箇条書きで3つ」に4つで答えた場合は、ちょうど
  3つにまとめ直させます(数が合った時だけ採用)。「敬語を使わずに」「友達に話すように」
  と頼まれたら、その回答はです・ます調を使いません。
- **覚えたことを素直に答えます。** 「私の名前は?」に、知っているのに「まだ聞いて
  いません」と書き出すことが 5 回中 3 回ありました(ペルソナにあった決まり文句に
  引っぱられていたため)。言い方を変えて 8 回中 8 回、正しく答えるようになりました。

## 率直モードについて

**このAPIは既定で率直モードです。** 医療・法律・セキュリティなどの一般知識、
辛口の意見、フィクション上の暴力描写といった話題で、定型的な免責文や
「専門家に相談してください」で逃げることなく、聞かれたことに直接答えます。

一方で、次の内容は**モード設定に関わらず常に拒否**します。

- 児童を性的に扱う内容
- 爆発物・毒物など、大量に人を傷つける手段の具体的な製造手順
- 実在の個人を標的にした攻撃・嫌がらせ・住所特定などのなりすまし

この線引きは `src/rula/persona.py` の `HARD_LIMITS` に書かれており、呼び出し元の
システムプロンプト(`system`)より後ろに常に付くため、そこからは上書きできません。
ただしプロンプト上の制御であり、重みに含まれるものではありません(`NOTICE` を参照)。

## 外部公開時の注意

**URLとキーを知る人は、あなたのPCのGPUを使えます。**

| 保護 | 内容 |
|---|---|
| 認証 | 全エンドポイントでAPIキー必須(`/health` を除く) |
| レート制限 | 20リクエスト / 60秒(キー単位) |
| 入力長 | 1メッセージ 4000文字まで |
| 同時実行 | 1件ずつ(GPUは1枚。同時に来た分は順番待ち) |
| 待ち受け | `127.0.0.1` のみ。LANにも公開しません |
| タイムアウト | 生成300秒 |
| ログ | 検索クエリのみ記録。**メッセージ本文は記録しません** |

保護は実質APIキー1枚です。より厳しくするならCloudflare Accessの併用を検討してください。

## 必要環境

- Python 3.10以上
- NVIDIA GPU(VRAM 8GB以上)
- 空きディスク 約4GB
- Cloudflareに登録済みの独自ドメイン(固定URLの場合)

GPUが無くてもCPUで起動しますが、1回の応答に数分かかるため実用的ではありません。
